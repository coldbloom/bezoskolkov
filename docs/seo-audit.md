# SEO-метаданные ОКНО ЩИТ

Аудит: 28 сентября 2026 года. Проверены исходники `plenki`, структура `medtaxi-evp` и HTML статического экспорта. Данные о показах, позициях и частотности запросов из Яндекс Вебмастера, Wordstat и Search Console не предоставлены. Целевые группы ниже выбраны по содержанию сайта и географии работы, а не по измеренной частотности.

## Сравнение с medtaxi-evp

В референсе используются общие метаданные layout, переопределения страниц, SEO-поля каталога услуг, собственный canonical каждой посадочной страницы, Open Graph/Twitter и связанные сущности JSON-LD. Полезный принцип — конкретная услуга и география в метаданных, согласованные с содержанием страницы.

В `plenki` уже был общий `createPageMetadata`, корректный `metadataBase`, canonical страниц, социальные превью, robots.txt и sitemap. Поэтому структура сохранена и дополнена. По одному репозиторию нельзя определить, какая доля хорошего ранжирования `medtaxi-evp` обеспечена метатегами.

| Область | До аудита | Внесённое изменение |
| --- | --- | --- |
| Главная | Title описывал материал; география отсутствовала в title и description | В title добавлены установка и Юг России; в description — объекты и расчёт по фото/размерам |
| Региональные страницы | Описание по одному шаблону с заменой города | Отдельные описания с соответствующей географией и объектами; установка в title |
| Canonical | Уже были корректные абсолютные адреса в HTML через metadataBase | Адрес явно формируется общим helper и используется также в OG и JSON-LD |
| `/regions/yug-rossii/` | Canonical вёл на `/`, но title/description отличались от главной | Canonical, title, description и социальные метаданные совпадают с главной; дубль по-прежнему исключён из sitemap |
| JSON-LD лендингов | Organization, WebSite, Service, FAQPage; не было WebPage | Добавлен WebPage со ссылками на WebSite, Service, FAQ и основное изображение |
| Индексирование | `index, follow` | Сохранено; Googlebot разрешены крупные превью и сниппеты без заданного сайтом ограничения длины |
| Keywords | Общий список, включая антивандальную плёнку, наследовался даже юридическими страницами | Короткие тематические списки только на главной и региональных лендингах |
| Подтверждение сайта | Не было настройки verification | Необязательные переменные для собственных кодов Google и Яндекса |
| Контроль экспорта | Проверялись наличие description/canonical и общая структура | Проверяются единственность тегов в head, уникальность текстов, согласованность canonical/OG/sitemap и связи JSON-LD |

## Главная страница

**Title:** Противоосколочная плёнка на окна — установка на Юге России | ОКНО ЩИТ

**Description:** Установка защитной противоосколочной плёнки на окна квартир, домов, офисов и витрин на Юге России. Подбор под остекление, расчёт стоимости по фото и размерам.

**Canonical:** корень сайта из `NEXT_PUBLIC_SITE_URL` с завершающим `/`.

`og:title`, `twitter:title`, `og:description`, `twitter:description` используют те же тексты. `og:url` совпадает с canonical. Изображение превью — `/og-image.png` на домене из `NEXT_PUBLIC_SITE_URL`, 1200 × 630. Надпись с доменом на картинке также формируется из этой переменной при сборке.

Источники: `homePageData` и helper в `lib/seo.ts`; описания регионов — `lib/regions.ts`. Главная и её дубль получают одинаковые данные через `getProtectionPageData`.

Главная охватывает услугу в целом, региональные страницы — местный спрос. Для каждого региона сохранён собственный canonical. Указание canonical регионов на главную мешало бы этой структуре.

## Публикация и измерение

1. Перед сборкой проверить `NEXT_PUBLIC_SITE_URL`. При необходимости заполнить `GOOGLE_SITE_VERIFICATION` и `YANDEX_SITE_VERIFICATION` значениями `content` из собственных кабинетов. Пустые значения не выводятся в HTML; чужие коды из референса не используются.
2. Выполнить `yarn build` и `yarn check:export`, разместить содержимое `out/` на хостинге. Изменения в репозитории сами по себе не обновляют опубликованный сайт.
3. На хостинге согласовать HTTPS, основной домен без www и завершающие слеши. При наличии альтернативных адресов настроить постоянные перенаправления на соответствующие canonical. Статический экспорт Next.js не настраивает эти HTTP-перенаправления.
4. После публикации проверить выбранный поисковиком canonical главной, отправить sitemap и запросить переобход главной/региональных страниц в кабинетах поисковых систем.
5. Сравнивать показы, клики, CTR и позиции по страницам и группам запросов. Для усиления региональных страниц добавить реальные местные работы, фотографии и условия выезда; сейчас значительная часть их содержимого общая.

Canonical помогает объединять дубли и является сигналом, а не обязательной командой для поисковика. Title/description влияют на представление страницы, но поисковые системы могут сформировать другие тексты сниппета. Open Graph/Twitter обеспечивают согласованное превью. Google не использует `meta keywords` для ранжирования. Эти изменения улучшают техническую основу SEO, но не гарантируют топ выдачи.

Существующая FAQPage-разметка описывает видимый FAQ. Она не рассматривается как способ получить расширенный FAQ-сниппет: Google прекратил показ этого формата в мае 2026 года.
