# Проверка ОКНО ЩИТ

Ниже сохранены результаты проверки production-сборки Next.js 16.3.6 от 27 сентября 2026 года. Проверки прежней модели согласия на аналитику относятся к той редакции; 4 октября 2026 года модель запуска счётчика изменена.

- `yarn build`: все страницы предварительно отрендерены (Static / SSG).
- `yarn lint`: ошибок нет.
- `yarn test`: в той редакции — 13 тестов согласия, запуска/отзыва аналитики, полей и payload формы.
- `yarn check:export`: 10 канонических страниц, региональный alias, sitemap, robots, изображения, актуальный бренд, юридические ссылки, отсутствие скрытого контента; в той редакции также проверялось отсутствие безусловной загрузки Метрики.
- Отдельный Chrome на локальной production-сборке: desktop 1440 px, mobile 390 и 320 px; переполнений нет.
- Проверены открытие, Escape и возврат фокуса модалки и мобильного меню; согласие формы изначально не отмечено.
- В прежней модели проверены отказ, сохранение решения после перезагрузки, повторное открытие настроек, принятие с заглушкой счётчика. В этих сценариях запросов к Яндексу и ошибок JavaScript не было.
- С искусственной задержкой сети проверен загрузочный экран при переходе на страницу компании.
- С отключённым JavaScript главный заголовок и содержимое видимы, телефон и обычные ссылки доступны. Лоадер не подменяет первый HTML.

Приём реальной заявки в той проверке не выполнялся: API и реквизиты оператора ещё не были предоставлены. Неотправленная заявка не отображается как успешная. Загрузка настоящего счётчика покрыта изолированными тестами с подменой внешнего сервиса; рабочий кабинет Яндекса не использовался.

Оптимизация сохраняет готовый HTML и адаптивные WebP основного экрана, откладывает модалку/мобильное меню и загрузку Метрики. Пять иллюстраций схемы уменьшены суммарно с 121 675 до 100 474 байт; favicon — с 25 931 до 1 338 байт; социальное превью — с 54 248 до 22 239 байт. Это размеры файлов, а не измерение Core Web Vitals на рабочем хостинге. Скорость реального сайта нужно измерить после публикации с его кешированием и сжатием.

Подробности решения с загрузчиком и настройки — в [README](../README.md). Правовая область проверки и неподтверждённые требования — в [privacy-audit.md](privacy-audit.md).

С 4 октября 2026 года Метрика запускается автоматически через `afterInteractive`, использует ID из `NEXT_PUBLIC_YANDEX_METRIKA_ID` и включает Вебвизор. При отключённом JavaScript используется `noscript`-пиксель. Баннер и настройки выбора аналитики удалены; результаты старых проверок отказа и отзыва не описывают текущую реализацию. Настройка и состав передаваемых событий описаны в разделе «Аналитика и cookie» в README.

Для новой реализации выполнены `yarn lint`, `yarn test` (14 тестов), `yarn build` и `yarn check:export`. Изолированные проверки счётчика покрывают ID из окружения, запуск при прежнем отказе, очередь целей до загрузки библиотеки, однократную инициализацию и просмотры при переходах. Проверка экспорта подтверждает наличие `noscript`-пикселя с настроенным ID во всех канонических страницах. Запросы в рабочий счётчик при этих проверках не отправлялись.

## Связка plenki — conditioners-server, 4 октября 2026

- Frontend: `yarn test` — 25 тестов, `yarn lint` и `yarn build` прошли. `yarn check:export` проверил 10 канонических страниц и региональный alias, включая метки всех телефонных ссылок в готовом HTML. Права публичного `out/` нормализованы через `chmod -R a+rX out`.
- Backend: `npm test` — 38 тестов, `npm run build` прошёл. Проверены CORS обоих endpoints, пустое имя plenki, согласие, контекст, отсутствие ложного успеха при сбое доставки, совместимость medtaxi/freeze/partner и карточки Telegram с правильным источником.
- `scripts/verify-api-contract.mjs` загрузил реальные функции frontend и реальные Express routers соседнего репозитория: 11 путей страниц, 44 заявки (`inline`/`modal`, с именем и без), 12 кликов с переходами и перезагрузкой. Проверены JSON preflight, `text/plain`/`keepalive`, источник, получатель, стабильная сессия и первоначальная рекламная атрибуция.
- Интеграционная проверка выполнялась на временном loopback-сервере с подменой Telegram. Рабочий API, бот и VPS не изменялись и тестовых заявок не получали. Это проверка контрактов кода; фактическая доставка после деплоя не подтверждена.
- В проверенном локальном окружении задан `NEXT_PUBLIC_API_URL=https://holodniypartner.ru/api`, но пуст `PERSONAL_DATA_OPERATOR_ADDRESS`. Первоначально `isLegalConfigured` блокировал отправку до `fetch`; это подтвердилось в опубликованном HTML `/regions/donetsk/`. Зависимость отправки от реквизитов оператора удалена: адрес API, телефон и согласие проверяются отдельно, реквизиты используются в документах. Для применения исправления нужно заново собрать и загрузить `out/`.
- После исправления прошли 35 тестов, lint, production build и `check:export`. Девять новых тестов выполняют обработчик `LeadFormClient` с подменой React hooks и API: обе формы отправляют запрос без реквизитов, ждут подтверждения, сохраняют значения при ошибке и проверяют телефон/согласие. В новом HTML главной и Донецка отсутствует прежняя блокировка. Production API ответил на CORS preflight `OPTIONS /api/feedback` статусом 204 с разрешённым origin `https://oknoshield.site`; реальная заявка в Telegram не отправлялась.

## Оптимизация главной, 4 октября 2026

Сохранён static export: HTML, основной текст, H1, canonical, Open Graph, JSON-LD и ссылки доступны до выполнения JavaScript. SSR на каждый запрос и ISR не включались. Новые клиентские обработчики не меняют эту архитектуру. `yarn build`, `yarn lint`, `yarn test` (26 тестов) и `yarn check:export` прошли; экспортная проверка дополнительно проверяет AVIF/WebP, eager/high priority для главной картинки и единственный соответствующий responsive preload.

Изменения:

- AVIF для двух крупных изображений с WebP fallback; 5 ширин вместо 3, `sizes` соответствует сетке. При одинаковой ширине AVIF меньше WebP на 22–27%; готовые файлы создаются из оригинальных PNG командой `yarn images:generate`.
- В статических иллюстрациях и CodeCake убран ненужный `next/image` runtime; размеры и ленивое получение изображений сохранены.
- Внешняя библиотека Метрики ждёт `load` и свободное время браузера на всех страницах. Очередь `ym`, `init`, просмотры и цели создаются до загрузки библиотеки. Вебвизор и выбранный ID сохранены. Проверены первоначальный визит, переход до загрузки и цели в очереди.
- Для Nginx подготовлен `deploy/nginx-performance.conf`: gzip текстовых ресурсов, immutable-кеш файлов с хешами, короткий кеш обычных картинок, перепроверка HTML/RSC и MIME для AVIF. Отдельный локальный nginx 1.27.2 подтвердил сжатие, заголовки, 304 и правильные 404; используются директивы, доступные в nginx 1.24. Рабочий VPS не изменялся.

На публичном сайте проверены HTTP-заголовки: HTML уже использовал gzip, а выбранные CSS и JavaScript не имели `Content-Encoding`, `Cache-Control` или `Expires`. Поэтому основной ожидаемый выигрыш зависит от применения подготовленного snippet на VPS, а не только от загрузки нового `out/`.

Лабораторные результаты: Lighthouse 13.5.0, Headless Chrome 154, мобильный экран 412×823, DPR 1.75, стандартная симуляция сети 1638.4 Kbps / RTT 150 ms и CPU ×4. Изолированный localhost отдавал production export. Внешние запросы Метрики/API блокировались; это не полевые показатели опубликованного сайта. При одинаковом сжатии правки кода уменьшили загрузку примерно на 7%; измеримого улучшения LCP сверх разброса этих запусков не получено. Первая серия исходного кода со сжатием всех типов включала один выброс Performance 61/TBT 2265 ms; остальные два запуска дали 95. Поэтому используются медианы и сохранены все прогоны. Скорость не выдаётся за гарантированный результат реального посетителя, а SEO 100 означает прохождение проверок Lighthouse, не обещание поисковых позиций.

Отдельно испытано `experimental.inlineCss`: FCP улучшился примерно на 0,09 с, LCP не улучшился, сжатый HTML вырос с 21,9 до 47,6 КБ. Настройка исключена из итогового кода; CSS остаётся отдельным и кешируемым.

Финальная проверка отдельным Chrome на ширинах 320, 390, 900 и 1440 px подтвердила видимый H1, отсутствие горизонтального переполнения, AVIF с отношением сторон 3:2 и единственным запросом hero без WebP-дубля. Пять схем и CodeCake загружаются с правильными размерами. Проверены открытие модалки, Escape и возврат фокуса, мобильное меню, переход на страницу компании и назад, прямой вход на региональную страницу. Ошибок JavaScript, гидратации и локальных 404 нет. Отдельный контекст с выключенным JavaScript подтвердил видимый заголовок и основное содержимое. Реальные формы и телефонные клики не отправлялись.
