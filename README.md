# ОКНО ЩИТ — oknoshchit.site

Сайт на Next.js 16 с готовым HTML для всех страниц. Сборка экспортируется в `out/` и не требует Node.js на хостинге.

## Сборка и проверка

```bash
yarn install --immutable
yarn build
yarn lint
yarn test
yarn check:export
```

Перед сборкой задайте `NEXT_PUBLIC_SITE_URL` и телефоны из `.env.example`. Канонические адреса, sitemap, robots.txt и номера в HTML фиксируются **во время сборки**; после изменения переменных сайт нужно пересобрать.

Основной контент, заголовки, ссылки, JSON-LD и юридические страницы рендерятся Server Components при сборке (SSG). Они доступны поисковым роботам без JavaScript. Это готовый сервером HTML, без необходимости выполнять SSR на каждый запрос. Клиентский код нужен только для интерактивных элементов. Модальное окно и меню подгружаются при открытии.

Загрузочный экран `components/PageLoading` включается при переходах через официальный `useLinkStatus` в `NavigationLink`. Корневой `app/loading.tsx` намеренно не используется: на проверенных Next.js 16.3.0 и 16.3.6 его Suspense-граница оставляла основной контент static export в скрытом сегменте до выполнения JavaScript. Это нарушало доступность сайта без JS. Новый загрузчик не задерживает первый показ страницы; быстрые переходы обходятся без вспышки скелетона. `check:export` проверяет отсутствие скрытых сегментов React во всех публичных страницах.

Размещайте **содержимое `out/`** в корне сайта. Хостинг должен отдавать `index.html` для URL с завершающим `/`, перенаправлять адреса без завершающего `/` на канонический URL и возвращать статус HTTP 404 вместе с `404.html` для несуществующих страниц. Проверьте MIME-типы для `.webp`, `.png`, `.xml` и `.txt`. Для ускорения включите Brotli или gzip и длительное кеширование файлов в `/_next/static/`. Не загружайте на хостинг `node_modules`, `.next` и `assets/originals`.

Оригиналы двух больших иллюстраций находятся в `assets/originals/`; оптимизированные варианты шириной 768, 1280 и 1536 пикселей — в `public/`. При замене иллюстраций обновите все три размера WebP и проверьте результат командой `yarn check:export`.

Единый исходник логотипа — `app/icon.svg`: его использует `BrandMark` в шапке, футере и загрузчике. Макет превью `assets/og-image.svg` ссылается на тот же знак. Команда `yarn brand:generate` обновляет из этого источника favicon и PNG для социальных сетей; скрипт использует `sharp`, поставляемый с Next.js. Локальные шрифты системы не создают запросов к внешним сервисам.

## Форма и обработка данных

Для включения отправки укажите `NEXT_PUBLIC_API_URL`, `PERSONAL_DATA_OPERATOR_NAME` и `PERSONAL_DATA_OPERATOR_ADDRESS`. Дополнительно можно указать ИНН, email для обращений и реквизиты обработчика. Не копируйте сведения другого бизнеса без проверки. Поля обеих форм доступны после загрузки JavaScript независимо от конфигурации отправки. До настройки посетитель видит доступный телефон; попытка отправки показывает явное сообщение и сохраняет введённые данные. Фиктивное сообщение об успешной отправке не показывается. На время запроса поля блокируются, после ошибки снова доступны для исправления и повторной отправки.

Форма в модальном окне и в блоке расчёта использует один модуль. Обязательны телефон и отдельный, изначально пустой checkbox согласия. Имя и тип объекта необязательны. Запрос совместим с API примера: `POST <NEXT_PUBLIC_API_URL>/feedback`, JSON с `name`, `phone`, `message`, `personalDataConsent`, `consentVersion`, `consentedAt`. В `message` передаются бренд, регион и тип объекта. API должен возвращать успешный статус только после приёма заявки; содержимое HTML вместо ответа API не считается успехом.

Сервер приёма заявок в репозиторий не входит. Настройте HTTPS и CORS для `https://oknoshchit.site` либо проксирование `/api/feedback` на хостинге. Проверка данных и согласия, ограничение частоты запросов, сохранение доказательств согласия и удаление по сроку должны быть реализованы также на сервере. Не проверяйте реальную доставку вымышленными заявками в рабочий API.

Политика: `/privacy/`; отдельное согласие: `/personal-data-consent/`. Технический аудит, официальные источники и вопросы к владельцу инфраструктуры — в [docs/privacy-audit.md](docs/privacy-audit.md). Проверка frontend не подтверждает уведомление РКН, размещение баз данных и фактические процессы обработки.

## Аналитика и cookie

`SiteAnalytics` включён в корневой layout. В `lib/analytics.ts` замените `YANDEX_METRIKA_ID = Number("000111222")` на настоящий ID. Запись с ведущими нулями преобразуется явно, поскольку числовой литерал `000111222` недопустим в TypeScript. Заглушка намеренно не загружает сторонний счётчик.

Метрика загружается после явного согласия и завершения основной загрузки. До согласия, после отказа и при отключённом JavaScript запросов к Метрике нет. Вебвизор, автоматическая запись кликов/ссылок и e-commerce отключены; содержимое форм, query-параметры и fragment в события не передаются. Учитываются просмотры страниц и цели `phone_click`, `social_click`, `form_success`, `form_error`.

Выбор хранится 180 дней. Ссылка «Настройки cookie» в футере позволяет его изменить; отказ останавливает счётчик и очищает доступные сайту аналитические cookie/хранилища. Он не удаляет уже переданную статистику из Яндекса. Обновляйте версию согласия и документы при изменении целей обработки.

## SEO и публикация

Метаданные главной, canonical и настройки Open Graph/Twitter собраны в `lib/seo.ts`; отдельные описания регионов — в `lib/regions.ts`. Главная и `/regions/yug-rossii/` используют один набор SEO-данных с canonical на `/`. Остальные региональные страницы ссылаются на собственные адреса. `check:export` проверяет уникальность метаданных и согласованность canonical, OG, sitemap и JSON-LD в готовом HTML.

Для подтверждения прав на сайт можно задать `GOOGLE_SITE_VERIFICATION` и `YANDEX_SITE_VERIFICATION` перед сборкой. Нужны значения `content` из метатегов собственных кабинетов, без HTML-разметки. Подробный анализ, группы запросов и порядок проверки после публикации — в [docs/seo-audit.md](docs/seo-audit.md).

Региональные страницы доступны для индексации, но для сильного ранжирования их нужно дополнять настоящими локальными сведениями и примерами работ. Скорость и корректная разметка не гарантируют позиции в поиске.

Если старый домен уже использовался, настройте постоянные 301-редиректы на соответствующие пути `https://oknoshchit.site`, подтвердите новый домен в кабинетах поисковых систем и отправьте sitemap. Это настройка хостинга, DNS и кабинетов; `output: "export"` не выполняет серверные redirects/headers из `next.config.ts`.
